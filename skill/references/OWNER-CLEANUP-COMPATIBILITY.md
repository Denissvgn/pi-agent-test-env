# Owner cleanup compatibility and qualification

Package 4.8.0 is an experimental owner-proof candidate. It adds
`legacy_derived_v1`, cohort `application_owner_legacy_1` and reader contract
`application_owner_legacy_reader_1` version 1. Existing `runtime_finalization` and
`retained_terminals` receipt meaning and historical record/intent bytes remain.
The new method creates sidecars; it never upgrades an old record to schema 3,
repairs failed accounting or fabricates an original witness.

| Boundary | Supported behavior | Still required |
| --- | --- | --- |
| Standard workspace | Original host custody, exact mount topology and closed metadata interface are implemented. Standard conformance graphs are synthetic. | A real producer identity and complete source/instance premises must be reviewed and installed; no real standard family is currently registered. |
| Diagnostic disposable | One exact reviewed artifact-diagnostic producer/loader/runtime identity tuple is installed. ROOT/OUT/CLAIM stay retained; only the original disposable child can be discarded. | Complete actual CID, controller/helper waits, original host identity, private authority/metadata closure and fresh native gates. Real owner qualification is pending. |
| New proof graph | Intent/independent anchor/selection/terminal/index are immutable create-only records with closed versions, refs and budgets. | Original existing lease, stable current records, supported cohort, no unknown writer/holder and exact discard authority. |
| New reader | Complete passive graph validation uses no daemon/PID call, cleanup, repair or adoption. | Independently qualified policy/provider/read scope before importing product code or considering history admission. |
| Old reader | Present unsupported schema-2 fields deny under the older closed reader. | An obsolete binary cannot recognize the new anchor after whole-store loss. New-cohort use requires the anchor-aware reader; no retroactive crash guarantee. |
| Wider qualification | An owner receipt attests only to exact owned host files, with admission_authorized false. | Model/application/SDK integration, global actor/authority and credential-memory claims need their own actual evidence. |

The 37 portable vectors and native temporary-directory faults demonstrate
algorithm behavior. They do not constitute a real cleanup, approve a policy,
register a fixture producer, or qualify an endpoint/image/application. Missing
original facts remain unsupported after installation or release. Never replace
an old CID or host identity with another actor's data or a current stat.

An explicit owner operation checks all original premises, then reobserves the
original lease, typed current records, daemon/CID/name/label absence, relevant
writers and overlapping registered mounts/runroots, including read-only and
aliased holders. It does not stop another owner, launch a container/model or
retrieve a key. Descriptor checks constrain exact roots and preserve all
protected original metadata. No shared campaign parent is a discard target.

After publication loss or partial purge, retain intent/selection/anchor and any
immutable terminal. Do not retry automatically, delete proof to permit an older
client, overwrite a terminal, force-release, or restore failed flags to appear
clean. A later supported passive inspection can inspect a surviving complete
graph; it never performs repair or publication completion.

Use a fresh qualified provider process or otherwise verify loaded-code identity;
copying a new version over a running old provider is insufficient. Install the
entire verified package into a new staging location, preserve local conflicts
and explicitly switch consumers under their own policy. Source checkout tests,
release tags and review waivers do not authorize a campaign restart.

The final exact source/archive and applicable native/ARM64 Docker checks, review
and authorized promotion precede release. Real eligible owner cleanup/replay and
downstream SDK/native qualification are separate gates. Until measured, report
those scopes unqualified. Historical measurements retain their old source/model/
image/configuration identities. See [validation](../VALIDATION.md),
[qualification](../QUALIFICATION.md), [owner operations](APPLICATION-OWNER-CLEANUP.md)
and the [reader specification](APPLICATION-OWNER-READER.md).
