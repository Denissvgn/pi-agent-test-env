kind: changed

The bundled images now build from `node:24-trixie-slim`, a Debian release that still receives security fixes for Chromium, and the base and BuildKit images are pinned by digest in `skill/docker/pins.json`, so two builds of the same release start from the same bytes. The Dockerfile has no default base and the `--base-image` and `--buildkit-image` defaults are those pins; the upstream `fd` pin stays because its static build does not depend on the base. The `ensure-image` receipt names the base that was really used (`base_image`, `base_source`, `base_digest`), the BuildKit image (`buildkit`, with `id` and `repo_digests`) and a hash of the installed Debian package list (`package_list_sha256`). For a project's own `--dockerfile`, `base_image` is null and `base_references` lists its `FROM` references as written; a `--base-image` passed with it is still forwarded as the `BASE_IMAGE` build argument but is recorded only as `base_argument`, with `base_argument_in_from` saying whether a `FROM` line uses it. A fresh image probe must report the installed TypeBox and pi-schema versions and is refused as `image-incompatible` without them or on a mismatch with the reviewed Pi release; saved receipts are read as before. Images built before this change describe the earlier base only; every earlier qualification applies to those images, and the next release campaign has to qualify the new ones.
